# Internal Documentation Site — Design Spec

Date: 2026-09-29
Status: Approved by user, pending implementation plan

## Purpose

Turn this vault (`Unifolio-Notes`) from a Git repo you browse in an editor
into a deployed, browsable documentation site for a small set of named
stakeholders — polished enough to feel like a real product's docs (the
user's reference points were things like FastAPI/Stripe-style docs), not a
raw file listing.

**Audience:** a small, fixed set of stakeholders, not the public.
**Success criteria:** stakeholders can browse, search, and follow links
across the vault's structured records in a browser, gated behind one
shared password, with zero new recurring cost.

## Non-goals

- Per-person identity/SSO, individual login accounts, or per-viewer audit
  trails — explicitly ruled out in favor of one shared password.
- Full-text search inside evidence PDFs/screenshots — only their titles/
  filenames are searchable (see Search, below).
- Blog features, doc versioning, or multi-version nav — MkDocs Material is
  chosen partly because none of this is needed.
- Restructuring the vault's own folder layout or authoring workflow — the
  site is a read-only view over the existing 00-09 structure, generated by
  `sync-documentation` as always; this project does not change how content
  gets written.
- Introducing AWS resources — considered and rejected on cost-conversation
  grounds even though the incremental AWS cost would in fact have been
  negligible; the user's preference was to avoid touching AWS billing for
  an internal-docs side effort. Vercel was chosen instead.

## Content scope & navigation

- **Primary nav** (searchable, full content, mirrors the vault's existing
  numbered structure 1:1): Overview, Journey, Decisions, Investigations,
  Reference & How-tos, Architecture, Risks & Debt.
- **Secondary nav — "Evidence"**: a separate, visually lower-prominence tab
  covering `08-evidence/`. Every existing `08-evidence/...` citation already
  used throughout the structured records becomes a real in-site link
  landing here, preserving the vault's "every claim needs an evidence link"
  rule in a form a reader can actually click through, without evidence
  competing with primary content for attention. Non-markdown evidence
  (PDFs, screenshots, HTML mockups) is served as static files with a
  simple auto-generated index page per evidence subfolder — no hand-authored
  evidence pages.
- **Excluded entirely** (not published, not linked): `00-inbox/` (raw,
  unprocessed by definition), `09-archive/`, `.obsidian/`, `.claude/`,
  `.git/`, and vault-authoring files not meant for a reader (`CLAUDE.md`,
  `MAP.md`).
- **Landing page**: built from `01-overview/executive-overview.md` — what
  Unifolio is, what the site covers, and quick links into Journey/
  Decisions/Architecture, rather than a bare folder/file tree.

## Site generator & reading experience

**Choice: MkDocs + Material theme.**

Rejected alternative: Docusaurus — React/Node toolchain, adds
versioning/MDX/blog capabilities this project doesn't need (YAGNI). MkDocs
Material needs a single YAML config, ingests the vault's existing numbered
markdown folders close to as-is, and is the same tooling family used by
docs sites like FastAPI's — matching the "feel like real documentation"
goal directly.

Features used, all built into MkDocs Material (no extra services):

- **Diagrams**: Mermaid rendering via `pymdownx.superfences`, straight from
  fenced ` ```mermaid ` code blocks — no image exports to keep in sync.
  The vault's `MAP.md` and journey entries already use Mermaid, so this is
  a direct carry-over, not new authoring work.
- **Sections/structure**: content tabs, nested admonitions, collapsible
  sections, syntax-highlighted code blocks — all part of the same
  extension set as diagrams.
- **Hypothesis flagging**: admonition callout boxes (e.g. a distinct
  "hypothesis" style) give the vault's existing CLAUDE.md rule — never
  present an unverified claim from a raw conversation as settled fact — a
  visual form, instead of relying on prose alone.
- **Search**: Material's built-in client-side search plugin (Lunr-based,
  no server, no third-party service). Indexes full page content and
  headings, with title-boosting and typo tolerance, across all 154
  structured-record pages. Scope limit, stated explicitly: it does **not**
  index text inside PDFs/screenshots in the Evidence tier — only their
  filenames/index-page descriptions are searchable. A third-party indexer
  (e.g. Algolia DocSearch) was considered and rejected: its free tier
  requires the site to be publicly crawlable, which conflicts directly
  with the password-gate requirement.
- **Navigation/reading aids**: persistent left sidebar, right-side
  "on this page" outline for long records, light/dark mode toggle.
- **Branding**: palette and brand identity/logo to be supplied by the
  user; Material's default palette is the fallback until then. This is an
  external input dependency, not an open design question — nothing about
  the site's structure depends on which palette is used.

## Hosting

**Choice: Vercel, free Hobby tier.**

Rejected alternative: AWS (S3 + CloudFront + Route 53 + a CloudFront
Function for auth) — technically workable and would in fact have cost
approximately $0/month at this traffic level (CloudFront Functions: 2M
free invocations/month; CloudFront: 1TB/10M requests free, both
permanent free tiers; S3: pennies for ~380 small files; Route 53: the
hosted zone is already paid for, one more record is free). Rejected
anyway per explicit user preference to keep this effort off the AWS bill
entirely and move to a provider used only for this purpose.

- Static site (`mkdocs build` output) deployed on Vercel's free Hobby
  tier.
- Custom subdomain: **`internaldocumentation.unifolio.in`** — one new
  CNAME record on the existing Route 53 hosted zone for `unifolio.in`,
  pointing at Vercel. No AWS service involved beyond the DNS record; no
  new AWS cost.
- **Noted risk, not blocking**: Vercel's Hobby tier terms are scoped to
  personal/non-commercial use. For a low-traffic internal docs site for a
  small stakeholder group this is common practice, but not contractually
  watertight. User's explicit decision: use Hobby. (Pro, $20/month/seat,
  would remove the ambiguity if this is revisited later.)

## Access control

- **Single shared password**, not per-person identity — confirmed
  explicitly by the user (no need to add/remove individual access or see
  per-viewer activity).
- Implemented as a **Vercel Edge Middleware** function (free at this
  traffic level, runs on every request): checks the request's HTTP Basic
  `Authorization` header; any username is accepted, only the password is
  checked, against a value read from a Vercel environment variable at
  runtime (never committed to source). Missing/incorrect password →
  401 response with a `WWW-Authenticate` challenge, which makes the
  browser show its native password prompt — no custom login page to build
  or maintain.

## Build, deploy, and verification

- **Repo layout**: `mkdocs.yml` lives at the root of this same
  Unifolio-Notes repo — no new/second repo, no content duplicated into a
  separate `docs/` tree. `docs_dir` points at the repo itself; excludes
  (via MkDocs' exclude mechanism) remove `00-inbox/`, `09-archive/`,
  `.obsidian/`, `.claude/`, `.git`, `CLAUDE.md`, `MAP.md` from the
  published output. `08-evidence/` is included but placed in nav as the
  separate secondary Evidence section described above.
- **Deploy**: Vercel's native GitHub integration — connecting the repo is
  a one-time setup step; every subsequent push to `main` auto-triggers
  `mkdocs build` and deploys the result. No hand-written CI workflow, no
  AWS credentials/OIDC to manage (an approach actively considered and
  dropped along with the rest of the AWS path).
- **Build safety**: `mkdocs build --strict` — a broken internal link or
  nav error fails the build instead of shipping a dead link; on failure
  the previously-deployed version keeps serving, nothing goes offline.
- **Post-deploy verification** (manual, one-time after first launch, and
  spot-checked after any middleware change): confirm an incognito/
  logged-out request is actually challenged for the password (not served
  the site outright), and confirm nav/search render correctly.

## Cost summary

$0/month: Vercel Hobby tier, DNS record on an already-paid-for Route 53
zone, no AWS compute/storage/CDN resources introduced.
